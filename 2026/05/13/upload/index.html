OWASP Top10 ｜文件上传漏洞进阶复盘

—— 黑名单绕过、解析漏洞、Pikachu 靶场复现与防御全拆解

一、漏洞概述

文件上传漏洞是 OWASP Top10 中危害极高的漏洞类型，成因是后端未对上传文件做严格校验，导致恶意脚本文件被上传至服务器并执行。

核心风险：上传 WebShell、远程代码执行、服务器被接管。

常见校验方式与绕过场景：

  • 前端 JS 校验绕过
  • 黑名单后缀过滤绕过
  • 白名单 MIME 类型绕过
  • 服务器解析漏洞利用
  • 图片马 + 文件包含组合利用

二、深层漏洞原理

1. 校验逻辑漏洞

  • 仅在前端用 JS 限制文件类型，后端无校验
  • 后端仅拦截.php等危险后缀，未过滤.php3/.phtml/.phar等变种
  • 仅校验文件头（MIME 类型），未校验文件内容与后缀

2. 服务器解析漏洞

  • Apache 解析漏洞：文件名含.php，如xxx.php.xxx，会按 PHP 解析
  • Nginx 解析漏洞：文件名形如xxx.jpg/xxx.php，会按 PHP 解析
  • IIS 解析漏洞：xxx.asp;.txt 会被当作 ASP 文件解析

3. 组合利用：图片马 + 文件包含

  • 制作含 PHP 代码的图片马（如hack.jpg）
  • 上传图片马后，通过文件包含漏洞解析图片中的 PHP 代码，实现执行

三、Pikachu 靶场逐关复现

1. 客户端 JS 校验绕过

  1. 进入 “客户端校验” 关卡，页面 JS 限制只能上传图片

  2. 直接用 Burp 抓包上传请求，修改文件名后缀为.php

  3. 或禁用浏览器 JS，直接上传shell.php

  4. 上传成功，使用蚁剑连接

即可看到系统文件结构，也可以使用蚁剑虚拟终端进行操作

2. MIME 类型校验绕过

  1. 进入 “MIME 类型校验” 关卡，后端校验Content-Type字段

  2. 上传shell.php，抓包修改请求头的Content-Type: image/jpeg

  3. 绕过后端校验，文件成功上传并解析执行

3. getimagesize校验绕过

  1. getimagesize校验只检验文件头部

  2. 于是抓包，在文件内容里面添加GIF89a 代表gif文件

4. 图片马 + 文件包含组合利用

  1. 制作图片马：

    或将php文件格式改为可用于提交的格式。例2.php.png

  2. 上传图片马至 Pikachu 文件上传点

  3. 访问文件包含漏洞页面，构造 URL 包含上传的图片马路径

  4. http://127.0.0.1/pikachu/vul/fileinclude/fi_local.php?filename=..<反馈的文件地址>

  5. PHP 代码被解析执行，此时可使用蚁剑连接，实现 WebShell 利用

四、实战踩坑点总结

  1. 前端校验绕过后，后端仍有黑名单拦截，需结合多种绕过方式
  2. 解析漏洞利用受服务器版本影响，高版本 Nginx/Apache 已修复部分漏洞
  3. 图片马需结合文件包含漏洞才能执行，仅上传无法直接解析
  4. 部分靶场对上传文件做了随机重命名，导致无法直接访问文件路径
  5. 上传文件权限不足，即使成功上传也无法执行 PHP 代码

五、防御方案

  1. 白名单校验：仅允许上传指定后缀（如.jpg/.png/.gif），拒绝其他所有后缀
  2. 文件头校验：校验文件真实内容，而非仅依赖后缀或 MIME 类型
  3. 随机重命名：上传文件自动生成随机文件名，避免攻击者预测路径
  4. 存储目录限制：上传目录设置为不可执行权限，即使上传 PHP 文件也无法解析
  5. 文件类型二次校验：后端调用系统 API 识别文件真实类型，而非前端提交的信息
  6. WAF 防护：拦截包含 WebShell 特征的上传请求，如、eval`等关键字
