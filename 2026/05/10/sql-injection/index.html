SQL 注入漏洞深度复盘｜原理分类 + 手工注入流程 + 过滤绕过 + 防御方案 + Sqlilabs 实战

一、漏洞概述

1.SQL 注入是 Web 安全中 OWASP Top10 高危漏洞之一，成因是后端程序直接拼接用户可控输入到 SQL 查询语句中，未做过滤、转义与预处理。

2.攻击者可构造恶意 SQL 语句，篡改原有查询逻辑，实现拖库查表、数据泄露、权限绕过、甚至服务器远程命令执行。

3.常见出现场景：URL 参数？id=、网站登录框、搜索框、订单查询、请求头 User-Agent/Referer/Cookie 等可控位置。

4.风险等级：高危，普遍存在于代码不规范的 PHP/Java/ASP 业务系统中。

二、底层原理

1. 正常业务逻辑

后端接收用户参数后，直接将其拼接到 SQL 语句中执行，不对用户输入进行语义隔离。

2.SQL 注入原理：

预期行为：查询 id=1 的用户信息并返回结果。

恶意注入 payload 带入后：

传入 1' and 1=2 union select 1,database()-- '

语句片段 作用说明
id = '1' 用户输入的第一个 ' 提前闭合了 SQL 语句中的单引号，让原本的字符串查询提前结束
AND 1=2 恒假条件，让原查询返回空，方便后续用UNION注入的结果覆盖回显
UNION SELECT 1, database() 联合查询，将当前数据库名拼接到结果集中
-- ' 注释符 -- 注释掉原语句中剩余的单引号，避免语法错误

3.注入本质总结

  • 攻击者利用单引号闭合破坏了原有的 SQL 语义边界
  • 用 UNION 注入了新的查询逻辑，获取了原本不应该暴露的敏感数据
  • 核心问题：把用户输入当成了 SQL 代码执行，未做到数据与代码分离

三、SQL 注入分类

1. 按页面回显 / 交互方式划分

  • 联合查询注入（Union Query Injection）

    场景：页面能正常返回查询结果（如用户信息、文章列表）

    原理：通过UNION SELECT

    适用：Sqlilabs Less-1 这类有正常回显的场景

  • 报错注入（Error-based Injection）

    场景：页面会直接输出数据库错误信息

    原理：利用数据库报错机制（如updatexml()``extractvalue()）

    优势：无回显也能直接拿数据，适合无法使用UNION

  • 布尔盲注（Boolean-based Blind Injection）

    场景：页面只有 “正常 / 异常” 两种状态，无数据回显、无报错

    原理：通过AND (条件)

    适用：Sqlilabs Less-5 这类无回显关卡

  • 时间盲注（Time-based Blind Injection）

    场景：页面状态无差异，无法用布尔判断

    原理：通过sleep(秒)``benchmark()

    适用：Sqlilabs Less-9 这类完全无交互的场景

2. 按请求提交方式划分

  • GET 注入：参数直接出现在 URL 中（如?id=1），最常见、易测试
  • POST 注入：表单提交的参数可控（如登录框、搜索框），需要抓包改包测试
  • Cookie 注入：请求头中的 Cookie 字段被后端读取并拼接 SQL，容易被忽略

3. 按注入位置 / 影响面划分

  • 参数值注入：URL、表单中的业务参数直接可控，最基础的场景
  • HTTP 头注入：User-Agent、Referer、X-Forwarded-For等请求头被写入数据库
  • 二阶注入：恶意数据先存入数据库，后续被其他功能读取并执行，隐蔽性强

5爆表名

PS:information_schema

MySQL 5.0 及以上版本中，会自带一个名为information_schema的系统元数据数据库，它就像数据库的 “数据字典”，存储了所有库、表、字段的结构信息，是我们实现 SQL 注入中 “爆库→爆表→爆字段” 流程的关键。

在注入中，我们最常用到information_schema下的两张核心表：

  • tables表：存储所有表的信息，其中table_name字段记录了所有数据库中的表名，table_schema字段记录了这些表所属的数据库名。
  • columns表：存储所有字段的信息，其中column_name字段记录了所有数据库中的字段名，table_schema字段记录了这些字段所属的数据库名，table_name字段记录了字段所属的表名。

五、常见过滤绕过技巧

  1. 空格过滤：用 /**/、()、换行代替空格
  2. 关键字过滤：双写绕过 select→selselect、大小写混淆 Select
  3. 引号过滤：宽字节注入 %df%27 绕过单引号过滤
  4. 逗号过滤：用 JOIN 联表查询、LIMIT 偏移替代逗号
  5. WAF 简单绕过：URL 编码、多参数拆分、特殊字符穿插混淆规则

六、防御方案

  1. 强制使用预编译 SQL + 参数化查询，杜绝字符串拼接
  2. 对用户输入做白名单校验、特殊字符转义过滤
  3. 数据库账号最小权限配置，不给跨库查询、删改权限
  4. 关闭生产环境数据库错误详情前端回显
  5. 部署 WAF / 应用防火墙，拦截常见注入特征 Payload
  6. 代码审计阶段禁止直接拼接用户参数到 SQL 语句
