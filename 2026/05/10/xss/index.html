XSS进阶复盘——存储型+反射型+DOM-XSS原理防御全拆解

一、漏洞概述

XSS（跨站脚本攻击）属于 OWASP Top10 高频高危漏洞。

漏洞核心成因：后端未过滤、前端未编码。

用户可控输入被浏览器误解析为 JS 脚本执行。

XSS 分为三类，风险与利用方式完全不同：

  • 反射型 XSS（非持久化）
  • 存储型 XSS（持久化高危）
  • DOM-XSS（前端无日志隐蔽型）

真实危害：Cookie劫持、伪造登录、页面篡改、钓鱼攻击、批量窃取用户数据、后台权限接管。

二、深层漏洞原理

1. 反射型 XSS（非持久化）

  • 无数据库存储，属于“一次性反射触发”
  • 攻击链路：恶意参数传入 → 后端直接回显前端 → 浏览器执行脚本
  • 需要诱导用户点击恶意链接，时效性短、无法批量攻击

2. 存储型 XSS（持久化高危）

  • 恶意脚本存入数据库/文件，永久生效
  • 攻击链路：提交恶意代码 → 后端入库 → 所有访问用户自动中招
  • 无需单独诱导，危害范围最广，企业业务最忌惮

3. DOM-XSS（无后端参与）

  • 全程不经过后端、无日志、无后端过滤
  • 漏洞完全由前端 JS 渲染逻辑导致
  • 危险函数：innerHTML、outerHTML、document.write
  • 隐蔽性极强，常规 WAF 极易绕过

三、本地环境搭建（Pikachu靶场）

  • 环境依赖：PHP + MySQL 集成环境
  • 靶场部署：正常启动 Pikachu，导入数据库
  • 测试入口：Pikachu → XSS 模块三大关卡
    • XSS 反射型
    • XSS 存储型
    • XSS DOM 型
  • 环境确认：输入点可控、参数可回显、无默认编码拦截

四、Pikachu靶场逐关手工复现

1. 反射型 XSS 复现

  1. 打开Pikachu靶场，点击菜单栏 反射型XSS 进入对应关卡

  2. 页面存在可控输入框，输入内容会实时回显在页面中，无初始过滤

写入payload

也可以直接在输入框中输入payload，但是需要更改最大输入长度

post输入型可以通过抓包修改message参数为<script>alert(1)</script>得到相同结果

2. 存储型 XSS 复现

  1. 返回Pikachu XSS模块，进入 存储型XSS（留言板） 关卡
  2. 该页面为公共留言功能，所有用户均可查看留言内容，数据会持久化存入靶场MySQL数据库
  3. 在留言输入框中提交恶意Payload：<script>alert(1)</script>
  4. 提交成功后无需操作，刷新当前留言板页面，恶意脚本自动执行弹窗，其他用户打开这个页面也会出现弹窗
  5. 切换浏览器、匿名模式或更换账号访问该页面，依旧触发脚本执行，验证漏洞持久化特性
  6. 漏洞危害：一旦植入恶意脚本，所有访问留言板的用户都会被攻击，影响范围全覆盖

3. DOM-XSS 复现

  1. 进入Pikachu DOM型XSS 专属关卡，观察页面布局，无明显输入框，参数依托URL传参

  2. 右键查看页面源码，可发现前端JS代码直接获取URL中的text参数，传入innerHTML渲染页面

  3. 全程无后端校验、无数据提交、无日志记录，仅前端渲染逻辑漏洞

  4. 修改浏览器地址栏URL，拼接恶意参数：?text=

  5. 回车刷新页面，脚本直接触发执行，完成无后端参与的漏洞利用

  6. 漏洞核心特点：流量不会经过后端服务，传统WAF规则难以检测拦截，隐蔽性极强

五、踩坑点总结

  • 编码失效：单层编码易被解码识别，必须双层嵌套编码
  • 标签拦截：script 标签常被过滤，需掌握 img/svg 事件绕过
  • DOM 渲染坑：前端渲染有顺序，参数加载滞后会导致 payload 失效
  • 浏览器弹窗拦截：alert 易拦截，实战使用静默拿 Cookie 载荷
  • 存储型过滤失效：靶场基础过滤严格，需多重变形组合绕过

六、修复防御方案

  • 输入过滤：采用白名单机制，拦截恶意标签、事件、JS 关键字
  • 输出编码：前端渲染前强制 HTML 实体编码、JS 编码
  • 配置 CSP 策略：禁止内联脚本、限制外部脚本域名
  • Cookie 加固：开启 HttpOnly，禁止 JS 读取 Cookie
  • 前端代码修复：废弃 innerHTML、document.write 危险函数
  • WAF 防护：拦截 XSS 特征 payload 与恶意请求
