HTTP 请求方法与状态码详解

一、HTTP 核心基础

HTTP 是无状态、请求响应式协议，一次完整请求分为两部分：

请求：客户端发起，定义操作方式；响应：服务器返回，通过状态码告知请求结果。

二、HTTP 常用请求方法（RESTful 规范）

核心原则：方法对应操作语义，日常开发仅用5种核心方法，其余极少使用。

  • GET（查询）：只读获取资源，URL传参、可缓存、幂等，无请求体，适合数据查询、静态资源获取。
  • POST（新增）：提交数据创建资源，请求体传参、无缓存、不幂等，适合注册、表单提交、数据新增。
  • PUT（全量更新）：覆盖更新完整资源，幂等，需传递全部字段，缺失字段会被清空。
  • PATCH（局部更新）：仅修改指定字段，节省带宽，幂等，适合修改状态、头像、密码等局部操作。
  • DELETE（删除）：删除指定资源，幂等，多次请求结果一致。

GET vs POST 核心区别

核心区别详细总结（面试高频）：

  1. 语义不同（最核心）：GET 用于只读查询，不会修改服务器数据；POST 用于提交写入，用于新增、修改、提交数据。
  2. 传参方式不同：GET 参数拼接在 URL 地址栏中；POST 参数存放于请求体（Body）中。
  3. 缓存机制不同：GET 默认支持浏览器缓存，重复请求会读取缓存；POST 无缓存，每次都会请求服务器。
  4. 幂等性不同：GET 是幂等请求，多次请求结果一致，无副作用；POST 非幂等，多次提交可能产生重复数据（如重复下单、重复注册）。
  5. 数据长度限制：GET 受浏览器 URL 长度限制，无法传输大数据；POST 无长度限制，支持文件上传、大字段传输。
  6. 安全性：GET 参数暴露在地址栏和历史记录中，安全性极低；POST 参数隐藏在请求体，相对更安全，但同样可被抓包拦截，无法防止恶意攻击。
  7. 收藏与历史记录：GET 请求可被收藏、留存浏览器历史；POST 请求无法被收藏。

三、HTTP 状态码分类与实战速查

状态码看百位即可快速定位问题：2xx成功、3xx重定向/缓存、4xx前端错误、5xx服务端错误。

状态码 类型 核心含义 实战场景
200 成功 请求正常成功 所有接口正常调用、数据查询成功
201 成功 资源创建成功 新增用户、创建订单
301/302 重定向 永久/临时跳转 域名迁移、登录后页面跳转
304 缓存 资源未更新，走本地缓存 js、css、图片等静态资源缓存命中
400 客户端错误 请求参数/格式错误 JSON非法、缺失必填参数
401 客户端错误 未登录/Token失效 未携带凭证、登录过期
403 客户端错误 权限不足 已登录，但无操作权限
404 客户端错误 资源/接口不存在 接口地址写错、页面路径失效
405 客户端错误 请求方法不匹配 GET接口用POST请求
429 客户端错误 请求过于频繁 接口限流、高频刷请求
500 服务端错误 服务器内部报错 代码异常、数据库报错
502/503 服务端错误 网关错误/服务不可用 服务宕机、未启动、网关异常
504 服务端错误 网关超时 接口执行耗时过长

四、报错快速排查思路

4xx 问题→前端/请求侧：排查接口地址、请求方法、参数格式、登录权限、请求频率

5xx 问题→后端/服务侧：排查服务状态、代码日志、数据库连接、网关配置、接口超时

五、极简 RESTful 接口规范

查询(GET)、新增(POST)、全量更新(PUT)、局部更新(PATCH)、删除(DELETE)，按需搭配对应状态码，统一前后端协作规范。

六、总结

  1. 请求方法核心看语义，严格区分查询、新增、更新、删除；
  2. 状态码靠百位分类快速定位前后端问题。
