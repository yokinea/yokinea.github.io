DNS解析流程与DNS污染详解

前面我们掌握了 HTTP、HTTPS 安全传输原理，想要搞懂网页访问的完整流程，必须吃透 DNS 域名解析。本文详解DNS完整解析流程、递归与迭代查询、DNS污染原理，。

一、DNS 基础介绍

DNS（域名系统），是互联网的“通讯录”。

核心作用：将人类好记的域名，翻译成计算机可识别的IP地址。

网络通信本质是 IP 与 IP 的通信，浏览器无法直接识别域名，必须通过 DNS 解析完成转换，才能访问目标服务器。

二、完整 DNS 解析流程

用户输入域名按下回车后，会经历7层逐级查询，先查缓存、再查服务器，最终拿到真实IP。

  • ① 浏览器缓存：优先查询浏览器本地缓存，之前访问过的域名会直接留存IP，无需重复解析
  • ② 系统缓存：浏览器无缓存时，查询电脑本地 hosts 文件，看是否存在域名与IP的绑定记录
  • ③ 本地DNS服务器：本地无记录，向运营商DNS、公共DNS（阿里、腾讯DNS）发起解析请求
  • ④ 根域名服务器：本地DNS无法解析，请求全球根服务器，根服务器返回对应顶级域名服务器地址
  • ⑤ 顶级域名服务器：根据域名后缀（com/net/org）查询，返回权威域名服务器地址
  • ⑥ 权威域名服务器：最终查询域名注册的官方服务器，返回域名对应的真实公网IP
  • ⑦ 回传缓存：IP逐级回传给浏览器，浏览器缓存IP，随后发起TCP连接、请求网页数据

三、递归查询与迭代查询

DNS 解析全程包含两种查询方式，分工明确，是高频面试考点。

1. 递归查询

场景：客户端（浏览器） → 本地DNS服务器

特点：客户端只发起一次请求，不用管解析过程，由本地DNS服务器全权查询，最终直接返回成功IP或失败结果。

2. 迭代查询

场景：本地DNS服务器 → 根/顶级/权威服务器

特点：上级服务器不帮你全程查询，只返回下一级服务器地址，由本地DNS逐级向下查询，直到拿到结果。

四、DNS 污染原理与解决方案

1. 什么是DNS污染

DNS污染属于网络劫持攻击，是域名解析异常、网站打不开、跳转错误页面的常见原因。

2. 污染核心原理

传统DNS解析基于 UDP明文传输，无加密、无校验、端口固定，存在严重安全漏洞。

中间人可拦截用户的DNS查询请求，伪造虚假的IP解析结果，提前返回给客户端，覆盖真实的解析数据。导致客户端拿到错误IP，无法访问真实网站。

3. 常见解决方式

  • 使用加密DNS（DoH/DoT协议），杜绝明文劫持
  • 切换公共可信DNS服务器（阿里DNS、腾讯DNS）
  • 本地hosts文件手动绑定域名与真实IP

五、总结

  1. DNS 核心工作：域名解析为IP，是网页访问的第一步。

  2. 解析顺序：浏览器缓存 → 系统hosts → 本地DNS → 根服务器 → 顶级服务器 → 权威服务器。

  3. 客户端查本地DNS是递归，本地DNS查上级服务器是迭代。

  4. DNS污染本质是UDP明文劫持、伪造解析IP，加密DNS可有效规避。
