Linux网络相关命令

上一篇我们掌握了Linux进程管理全套操作，本篇继续深耕Linux运维核心——网络命令。服务器网络不通、端口不通、外网访问异常、延迟丢包、IP配置故障，全部依靠网络命令排查。本文汇总工作、面试最高频的Linux网络指令，零基础可直接上手，适配排查、部署、面试背诵。

一、网络基础信息查看命令

用于查看本机IP、网卡信息、网络配置，是排查网络问题的第一步。

命令 核心作用 实战用法
ip addr 查看本机网卡、IP、MAC地址 替代旧版ifconfig，查看所有网卡状态、内网IP、网卡是否启用
hostname 查看/修改主机名 hostname 查看主机名；hostname xxx 临时修改主机名
route 查看系统路由表 查看默认网关、路由转发规则，排查跨网段访问异常

二、网络连通性测试命令

排查主机是否在线、网络是否通畅、延迟丢包的最基础命令。

1. ping 连通性测试

核心作用：测试本机与目标主机网络是否互通，检测延迟与丢包。

常用用法：

  • ping 114.114.114.114 测试外网连通性
  • ping 域名 测试域名解析与网络连通
  • ping -c 4 IP 指定发送4次数据包后停止，避免无限ping

排查逻辑：ping不通目标主机 → 检查本地网络、网关、防火墙、对方服务状态。

2. traceroute 路由追踪

核心作用：追踪数据包从本机到目标主机经过的路由节点，定位卡顿、丢包节点。

用法：traceroute 目标IP/域名

实战场景：网站访问慢、接口延迟高，定位是本地、中转节点还是服务器问题。

3. mtr 综合网络检测

结合 ping + traceroute 功能，精准统计各节点丢包率，是排查线上网络抖动、随机丢包的神器。

三、端口与连接状态查看命令

排查端口占用、服务监听、TCP连接、并发连接数的核心命令，面试、部署必问。

1. netstat 网络状态统计

用于查看端口监听、TCP/UDP连接、进程占用端口、连接状态。

高频组合命令（工作必背）：

  • netstat -tulpn 查看所有监听端口、对应进程PID（排查端口占用核心）
  • netstat -an | grep ESTABLISHED 查看当前正在活跃的TCP连接数
  • netstat -an | grep 8080 查看指定端口连接状态

参数释义：t(TCP)、u(UDP)、l(监听)、p(进程名)、n(数字端口不解析)

2. ss 新型连接查看命令

替代 netstat，速度更快、信息更全，适合高并发服务器查看连接。

常用：ss -tuln 查看所有监听端口；ss -s 统计整体连接情况。

四、域名解析与网络下载命令

排查DNS解析、服务器拉取资源、接口访问测试必备。

命令 作用 实战场景
nslookup 域名解析测试 查看域名解析IP，排查DNS污染、解析异常
dig 详细DNS解析查询 查看解析链路、服务器、TTL，解析问题深度排查
curl 命令行访问接口/网页 测试接口是否通、服务是否启动、返回状态码
wget 网络文件下载 服务器在线下载安装包、资源文件

五、网络故障快速排查流程

线上网络异常、服务访问不通，固定排查顺序，高效定位问题：

  1. ping 外网 确认本机网络是否正常
  2. ping 目标IP 确认服务器是否可达
  3. nslookup 检查域名解析是否正常
  4. netstat/ss检查端口是否监听、是否被占用
  5. curl 接口 测试服务响应是否正常
  6. 检查防火墙、安全组是否放行端口

六、重点事项

1. netstat 和 ss 的区别？

netstat 兼容性强、使用经典；ss 是新一代命令，查询速度更快、高并发场景性能更好、连接统计更精准，生产环境优先使用 ss。

2. 端口监听正常但外网访问不通？

大概率是服务器防火墙、云服务器安全组未放行对应端口，端口监听代表本地服务正常，外网访问需要网络权限放行。

3. curl 命令的实战意义？

服务器无图形界面，无法打开浏览器，通过 curl 快速测试接口连通性、HTTP状态码、响应内容，是后端与运维排查接口的核心方式。

七、总结

  1. 查IP网卡用 ip addr，测连通性用 ping、路由追踪用 traceroute。

  2. 查端口、连接、端口占用优先 netstat/ss，解决90%端口问题。

  3. 解析异常用 nslookup/dig，接口测试用 curl，资源下载用 wget。

  4. 网络不通固定流程排查：本机网络 → 对方主机 → DNS解析 → 端口监听 → 防火墙策略。
