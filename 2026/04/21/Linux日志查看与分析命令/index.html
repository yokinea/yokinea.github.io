Linux日志查看与分析命令

上一篇我们掌握了Linux全套网络排查命令，本篇讲解日志查看与分析。线上服务报错、接口异常、程序崩溃、系统故障，99%的问题都需要通过日志定位根源。日志分析是运维、后端、安全岗位的核心实战技能，也是面试高频考点。

一、Linux日志核心基础

日志是系统和程序的运行记录，包含报错、警告、正常请求、异常堆栈、运行状态等关键信息。

Linux 核心设计：一切问题皆可查日志，排查故障优先看日志，而非盲目重启服务。

系统默认日志统一存放目录：/var/log/

二、基础日志查看命令

适用于快速读取、实时监控、分页查看日志，适配不同日志文件大小场景。

命令 核心作用 实战场景
cat 一次性读取全部日志内容 只适合小日志、配置文件，禁止用于GB级大日志文件
less 分页查看日志，支持上下翻页、搜索 查看中大日志文件，操作灵活，退出按 q
head 查看日志头部前N行 head -n 20 log.txt 查看日志前20行初始化信息
tail 查看日志尾部、实时监控日志 tail -n 20 查看最新20条日志；tail -f 实时刷新日志（排查线上实时报错神器）

三、日志筛选与过滤核心命令

日志数据量大、内容繁杂，通过过滤命令精准筛选报错、关键字、异常堆栈。

1. grep 关键字过滤

核心作用：根据关键字筛选匹配的日志内容，排查报错核心指令。

常用实战用法：

  • grep "error" app.log筛选所有包含error报错的日志
  • grep "warn" app.log 筛选所有警告日志
  • grep -i "error" app.log 忽略大小写筛选报错
  • grep -v "info" app.log 反向过滤，剔除正常info日志，只看异常
  • grep "error" -A5 -B5 app.log 筛选error关键字，并展示前后5行日志，完整查看报错上下文

参数释义：-A 匹配后几行、-B 匹配前几行、-C 匹配前后几行

2. 管道组合筛选

多命令组合，实现精准二次过滤，复杂场景必备：

  • tail -f app.log | grep error 实时监控并只展示报错日志
  • cat app.log | grep timeout 筛选所有超时异常日志

四、日志统计与分析命令

用于统计报错次数、接口请求量、异常频次，量化分析线上问题。

1. wc 统计行数

用法：grep "error" app.log | wc -l

作用：统计日志中报错总条数，判断异常是偶发还是批量故障。

2. sort & uniq 去重统计

用于统计重复报错、重复请求，定位高频异常问题。

实战：筛选异常接口并统计请求次数，快速定位故障接口。

五、系统默认核心日志文件

排查系统故障、登录异常、服务启动失败，优先查看以下系统日志：

  • /var/log/messages：系统全局日志，记录系统大部分日常异常、服务启动报错
  • /var/log/secure：安全日志，记录SSH登录、账号密码、暴力破解、登录失败记录（安全排查核心）
  • /var/log/cron：定时任务日志，记录crontab任务执行、失败异常
  • /var/log/boot.log：系统开机启动日志，排查开机服务启动失败问题

六、日志切割与清理常识

线上日志持续增长，会占用磁盘空间导致服务器爆满，日常需规范处理：

  • 禁止直接 rm -rf 删除正在写入的日志文件，会导致日志空洞、服务无法写入新日志
  • 生产环境使用 logrotate 自动切割日志，按天/按大小分割、自动归档、自动删除过期日志
  • 清空正在使用的日志：> app.log 安全清空，不影响服务写入

七、线上故障日志排查标准流程

  1. 实时监控日志：tail -f 日志文件 复现问题
  2. 筛选核心异常：grep 匹配 error、warn、timeout、exception 关键字
  3. 查看上下文日志，定位报错代码行、接口、参数
  4. 统计异常频次，判断是偶发bug、网络抖动还是批量故障
  5. 结合系统日志排查服务器层面问题（资源、权限、服务异常）

八、重点事项

1. 为什么不能直接rm删除正在写入的日志？

Linux文件删除仅删除文件指针，服务进程仍持有文件句柄，磁盘空间不会释放，且新日志无法写入，导致日志服务异常、磁盘占用居高不下。推荐使用 > 日志文件 清空。

2. 如何精准排查偶发线上报错？

通过 grep 筛选异常关键字 + 展示上下文，结合 wc 统计报错频次，定位问题触发条件与影响范围。

3. 安全日志主要排查什么？

/var/log/secure 记录所有远程登录行为，可排查暴力破解、异常登录、权限盗用等安全风险。

九、总结

  1. 小文件用cat、大文件用less、实时监控用tail -f，适配不同日志场景。

  2. grep是日志分析核心，可精准筛选异常、查看上下文、快速定位bug。

  3. 系统故障看messages、登录安全看secure、定时任务看cron。

  4. 线上禁止直接删除运行中日志，使用专业方式清空与切割，避免故障扩大。
