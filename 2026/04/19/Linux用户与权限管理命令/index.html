Linux用户与权限管理命令

上一篇我们掌握了Linux文件操作核心命令，本篇继续讲解Linux体系核心基石：用户与权限管理。Linux是多用户、多任务操作系统，权限管控是系统安全的核心，也是服务器部署、项目上线、安全运维的高频必考知识点。

一、Linux 用户基础概念

Linux 系统中，所有文件、进程、服务都依赖用户权限运行，核心分为两类用户：

  • 超级管理员 root：最高权限用户，拥有系统所有操作权限，无任何权限限制，UID 固定为 0
  • 普通用户：手动创建的受限用户，仅拥有自身家目录权限，无法随意修改系统配置，UID 从 1000 开始

核心配置文件：/etc/passwd（用户信息）、/etc/group（用户组信息）、/etc/shadow（用户密码信息）

二、用户与用户组管理命令

日常运维中用于创建、删除、修改用户，适配多人服务器权限分配场景。

命令 核心作用 实战用法
useradd 创建新普通用户 useradd test 创建test用户，自动生成/home/test家目录
userdel 删除用户 userdel -r test 删除用户并同步删除家目录，彻底清理用户数据
passwd 设置/修改用户密码 passwd test 为指定用户设置密码，普通用户仅可修改自身密码
groupadd 创建用户组 groupadd dev 创建dev开发用户组，用于批量管理权限
usermod 修改用户信息 usermod -aG dev test 将test用户加入dev附属组
id 查看用户UID、GID、所属组 id test 快速查看用户权限身份信息

三、Linux 文件权限核心原理

Linux 所有文件/目录都具备三类权限、三种身份，权限决定谁能读、写、执行文件。

1. 三种身份

  • 所有者（u）：文件创建者/归属用户，权限优先级最高
  • 所属组（g）：同组内所有用户，共享组权限
  • 其他用户（o）：非所有者、非同组的其他所有用户

2. 三种基础权限

权限字符 数字权限 文件权限作用 目录权限作用
r（读） 4 可读取、查看文件内容 可查看目录内文件列表
w（写） 2 可修改、编辑文件内容 可新增、删除、移动目录内文件
x（执行） 1 可运行脚本、程序文件 可进入目录、切换工作目录

权限计算规则：身份权限为 rwx 对应数字相加，如 rw- = 6、r-x = 5、rwx = 7

四、权限修改核心命令

1. chmod：修改文件权限（最常用）

用于修改所有者、所属组、其他用户的读写执行权限，分为数字赋值和字符赋值两种方式。

  • 数字权限：chmod 755 test.sh 所有者7(rwx)、组和其他用户5(r-x)，目录/脚本通用权限
  • 数字权限：chmod 644 test.txt 普通文件默认权限，仅所有者可修改
  • 字符权限：chmod u+x test.sh 给所有者添加执行权限
  • 递归修改：chmod -R 755 /test 递归修改目录内所有文件权限

2. chown：修改文件归属

用于修改文件的所有者和所属组，解决权限不足、文件归属异常问题。

  • chown test:test test.txt 修改文件所有者和所属组为test用户
  • chown -R test:test /test 递归修改目录及所有文件归属

五、高级权限与提权操作

1. sudo 提权

普通用户临时获取 root 管理员权限，无需登录 root 账号，兼顾安全与便捷。

使用前提：普通用户需在 /etc/sudoers 文件中被授权。

用法：sudo rm -rf test/ 以管理员权限执行删除命令

2. su 切换用户

用于切换登录用户身份，全程切换环境变量。

  • su root 切换为root用户，需输入root密码
  • su test 切换为普通用户

六、重要事项

1. 755、644 权限含义

  • 755：所有者可读可写可执行，其他人可读可执行，适用于目录、脚本、程序
  • 644：所有者可读可写，其他人仅可读，适用于配置文件、文本文件

2. 目录必须拥有执行权限

目录没有 x 执行权限，即使有读权限也无法进入目录、查看内部文件，是新手最容易踩坑的知识点。

3. sudo 与 su 区别

  • su：完整切换用户身份，需要目标用户密码，权限完全移交
  • sudo：临时提权，使用自身密码，权限可控、更安全，生产环境首选

七、总结

  1. Linux 安全核心：用户区分身份，权限管控操作，杜绝权限泛滥。

  2. 三类身份、三种基础权限，数字快速赋值是日常运维主流用法。

  3. chmod 改权限、chown 改归属，递归参数 -R 批量处理目录权限。

  4. 生产环境禁止普通用户权限过大，优先使用 sudo 临时提权，保障系统安全。
