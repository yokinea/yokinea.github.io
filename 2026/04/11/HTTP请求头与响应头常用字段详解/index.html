HTTP请求头与响应头常用字段详解

前面我们掌握了 HTTP请求方法 + 状态码，本篇继续补全 HTTP 核心基础：请求头（Request Header）与响应头（Response Header）。

请求头、响应头是前后端交互的「隐藏参数」，用来传递身份、缓存、编码、跨域、设备、cookie 等关键信息，是调试接口、解决跨域、缓存问题、登录鉴权的必备知识。

一、Header 基础概念

  • 请求头（Request Header）：浏览器/客户端发给服务器的附加信息
  • 响应头（Response Header）：服务器返回给浏览器的附加信息

Header 不参与业务数据传输，只负责协商通信规则、校验身份、控制缓存、跨域授权。

二、常用请求头字段

请求头字段 作用详解 实战场景
Host 指定请求的域名+端口 服务器区分多域名、虚拟主机
User-Agent 客户端身份标识（浏览器/设备信息） 后端判断移动端/PC端、爬虫拦截、设备统计
Content-Type 请求体数据格式 application/json、form-data、x-www-form-urlencoded
Accept 客户端能接收的响应数据格式 告诉服务器我只接收 json、图片、文本等类型
Authorization 身份认证令牌（最常用） 携带 Token、Bearer 登录凭证，接口鉴权
Cookie 客户端本地缓存的 Cookie 数据 会话保持、免登录、识别用户会话
Referer 请求来源页面地址 防盗链、统计流量来源、防止非法调用
Origin 请求源（协议+域名+端口） 跨域核心字段，服务器判断是否允许跨域
Cache-Control 客户端缓存策略 no-cache 不使用本地缓存，强制刷新
If-Modified-Since 资源最后修改时间 配合 304 缓存协商，判断资源是否需要更新

三、常用响应头字段

响应头字段 作用详解 实战场景
Content-Type 返回数据的格式与编码 返回 json、html、图片、文件流，指定编码 utf-8
Set-Cookie 服务器向客户端写入 Cookie 登录成功后下发会话 Cookie，保持会话
Access-Control-* 跨域允许配置 Access-Control-Allow-Origin 允许指定域名跨域
Cache-Control 服务端缓存控制 max-age 控制资源缓存时长
Last-Modified 资源最后修改时间 配合客户端实现协商缓存，返回 304
Location 跳转地址 301/302 重定向时，告诉浏览器跳转目标地址
Server 服务器软件版本 展示 nginx、tomcat 服务信息（一般生产隐藏）
Expires 资源过期时间 旧版缓存控制，现已优先 Cache-Control

四、注意事项

1. Content-Type 三种常见格式区别

  • application/json：前后端主流，传递 JSON 数据
  • x-www-form-urlencoded：普通表单提交，键值对格式
  • multipart/form-data：文件上传、带文件的表单提交

2. Origin 和 Referer 区别

  • Origin：只包含 协议+域名+端口，跨域必带
  • Referer：完整页面 URL，部分场景会被浏览器隐藏，不安全

3. 缓存核心配对

请求头 If-Modified-Since + 响应头 Last-Modified = 协商缓存，命中返回 304，减少服务器压力。

4. 跨域核心响应头

Access-Control-Allow-Origin：配置允许跨域的域名，解决前端跨域报错。

五、总结

  1. 请求头：客户端告诉服务器「我是谁、我能接收什么、我带了什么凭证」。

  2. 响应头：服务器告诉客户端「返回的数据格式、能不能缓存、允不允许跨域、要不要跳转」。

  3. 掌握以上字段，足以搞定 接口调试、跨域问题、缓存优化、登录鉴权 所有日常场景与面试考点。
