HTTPS工作原理与加密

前面我们吃透了 HTTP 请求方法、状态码、请求响应头，本篇继续进阶核心重点：HTTPS 加密原理与握手过程。HTTPS 是网络安全、接口安全的核心基础。

一、HTTPS 基础介绍

HTTPS = HTTP + SSL/TLS 安全加密层

普通 HTTP 属于明文传输，存在三大风险：数据窃听、数据篡改、中间人冒充。

HTTPS 在 HTTP 基础上增加 SSL/TLS 加密机制，实现：防窃听、防篡改、防冒充，兼顾安全性与传输性能，是目前全网通用标准。

二、两种加密方式核心区别

HTTPS 不是单一加密，是对称加密 + 非对称加密组合使用。

加密方式 原理 优点 缺点
对称加密（AES） 加密解密使用同一个密钥 速度快、性能高，适合大量数据传输 密钥传输过程容易被劫持，不安全
非对称加密（RSA） 公钥加密、私钥解密，密钥成对出现 安全性极高，密钥不会泄露 运算极慢，不适合传输业务数据

最终方案：用非对称加密协商密钥，用对称加密传输数据，兼顾安全和速度。

三、HTTPS 完整握手加密流程

HTTPS 通信分为两个阶段：TLS握手阶段（协商密钥）、数据传输阶段（加密通信）

1. TLS 握手阶段（建立安全通道）

该阶段只执行一次，目的是客户端与服务端协商出一致的会话密钥

  • 第一步：客户端Hello 客户端发送：TLS版本、加密套件列表、客户端随机数（Client Random）
  • 第二步：服务端Hello 服务端确认：选定加密套件、返回服务端随机数（Server Random）、下发CA证书（含服务器公钥）
  • 第三步：客户端校验证书 客户端验证证书合法性、域名、有效期，确认服务器真实可信，防止中间人冒充
  • 第四步：生成预密钥并加密传输 客户端生成随机预主密钥（Pre-master），使用服务器公钥加密发送给服务端
  • 第五步：服务端解密密钥 服务端使用自己的私钥解密，拿到预主密钥
  • 第六步：双方生成统一会话密钥 两端通过：客户端随机数 + 服务端随机数 + 预主密钥，算法生成一致的对称会话密钥
  • 第七步：握手完成 双方互发Finished报文，校验通道无篡改，握手结束

2. 数据传输阶段（加密通信）

握手成功后，后续所有接口数据、网页数据，全部使用 对称会话密钥 加密传输。

特点：速度快、安全性高、每次连接密钥随机，即使被抓包也无法解密数据。

四、核心注意事项

1. 为什么不能只用对称加密？

对称密钥需要双方同步，如果直接网络传输密钥，容易被中间人劫持，后续所有加密数据都会被破解，完全不安全。

2. 为什么不能只用非对称加密？

非对称加密运算速度极慢，网页、接口大量数据传输会严重卡顿，无法满足线上业务性能需求。

3. CA 证书的作用是什么？

证书由权威机构CA颁发，用于校验服务器身份。防止中间人伪造服务器、伪造公钥，是 HTTPS 防冒充的核心保障。没有合法证书，浏览器会直接提示不安全并拦截访问。

4. HTTPS 如何防止中间人攻击？

中间人无法伪造 CA 合法证书，无法篡改证书签名；同时中间人没有服务器私钥，无法解密预主密钥，无法生成会话密钥，因此无法窃听、篡改通信数据。

五、HTTP 与 HTTPS 核心区别

对比项 HTTP HTTPS
端口 80 443
安全性 明文传输，极不安全 加密传输，防窃听篡改
协议层级 应用层协议 HTTP + SSL/TLS 安全层
性能 速度快，无握手开销 略微消耗性能（握手过程）
证书 无需证书 必须CA合法证书

六、总结

  1. HTTPS 核心是非对称加密协商密钥，对称加密传输数据，安全与性能兼得。

  2. TLS 七步握手是为了安全生成随机会话密钥，保证每一次连接独立安全。

  3. CA 证书是 HTTPS 信任基石，杜绝中间人伪造服务器。

  4. 现代开发、上线项目必须使用 HTTPS，HTTP 已基本被淘汰。
